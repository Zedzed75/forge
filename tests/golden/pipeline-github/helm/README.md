# boutique

Boutique en ligne, chaine complete

Kubernetes/Helm project generated by [forge](https://github.com/). Every piece of
content in this repository is reproducible from `forge.yml`:

```bash
forge generate
```

## Prerequisites

| Tool | Minimum version | Role |
|---|---|---|
| `helm` | 3.12 | rendering and deployment of the chart |
| `kubectl` | 1.34 | access to the cluster |
| `kubeconform` | 0.6 | strict validation of the manifests |
| `make` | 4.0 | shortcuts for the everyday operations |

Target cluster: Kubernetes `>=1.34.0-0`.

## Environments

## Usage

### With make

```bash
make help                      # lists the available targets
make lint                      # helm lint on every environment
make template ENV=dev       # renders the manifests without applying them
make validate ENV=dev       # renders then validates with kubeconform
make validate-all              # validates every environment
make install ENV=dev        # deploys on the chosen environment
```

### Raw helm commands

Environment `dev`:

```bash
# Local rendering, with no contact with the cluster
helm template boutique ./charts/boutique \
  --namespace boutique-dev \
  --values ./charts/boutique/values.yaml \
  --values ./charts/boutique/values-dev.yaml

# Deployment
helm upgrade --install boutique ./charts/boutique \
  --namespace boutique-dev --create-namespace \
  --values ./charts/boutique/values.yaml \
  --values ./charts/boutique/values-dev.yaml \
  --wait --timeout 5m
```

Environment `prod`:

```bash
# Local rendering, with no contact with the cluster
helm template boutique ./charts/boutique \
  --namespace boutique-prod \
  --values ./charts/boutique/values.yaml \
  --values ./charts/boutique/values-prod.yaml

# Deployment
helm upgrade --install boutique ./charts/boutique \
  --namespace boutique-prod --create-namespace \
  --values ./charts/boutique/values.yaml \
  --values ./charts/boutique/values-prod.yaml \
  --wait --timeout 5m
```

## Validation

A rendered manifest must always pass the three following checks before reaching a
cluster:

```bash
# 1. Consistency of the chart
helm lint ./charts/boutique

# 2. Effective rendering of each environment
helm template boutique ./charts/boutique \
  --values ./charts/boutique/values-dev.yaml > /dev/null
helm template boutique ./charts/boutique \
  --values ./charts/boutique/values-prod.yaml > /dev/null

# 3. Conformance to the schemas of the Kubernetes 1.34 API
helm template boutique ./charts/boutique | \
  kubeconform -strict -summary -kubernetes-version 1.34.0 -
```

## Modifying the project

Two paths, according to the nature of the change:

1. **Structural change** (adding a component, an environment, a resource kind):
   modify `forge.yml` then run `forge generate --only helm --force` again — or
   `forge update --only helm`, which applies the evolutions of the template
   **without** overwriting your modifications.
2. **Operational tuning** (replicas, resources, hosts): modify
   `charts/boutique/values-<env>.yaml` directly.

Careful: a regeneration rewrites the files of the chart. The modifications made
by hand in `templates/` will be lost; carry them over into `forge.yml`.

## Tree

The `forge.yml` specification lives at the **root of the repository**, one level
above: it describes the whole service, not only its chart. What follows is the
content of `helm/`.

```
.
├── Makefile                        # lint / template / validate / install shortcuts
└── charts/boutique/
    ├── Chart.yaml                  # metadata of the chart
    ├── values.yaml                 # default values, entirely commented
    ├── values-dev.yaml               # divergences of the dev environment
    ├── values-prod.yaml              # divergences of the prod environment
    ├── README.md                   # documentation of the chart and of its values
    └── templates/                  # templates of the Kubernetes resources
```
