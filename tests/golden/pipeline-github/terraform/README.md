## What this project sets up, and what it does not

This project sets up **the base**: the partition the service lives in, its
budget, the identity that deploys there, what enters it and what leaves it. It
does not deploy the application — that is the role of a Helm chart or of a
manifest, which targets the namespace exposed here as an output.

Families retained:

- **`namespace`** — Creates the namespace the service is deployed in.
- **`quota`** — ResourceQuota and LimitRange: the budget of the namespace.

The complete catalogue, with the traps of each family, is consulted through
`forge catalog terraform` and `forge catalog terraform <family>`.

## Layout

A module written **once**, called **once per environment**. That is what
guarantees that `dev` and `prod` set
up the same objects, give or take the values.

```
.copier-answers.yml
.gitignore
.tflint.hcl
Makefile
README.md
modules/boutique/
  versions.tf
  variables.tf
  locals.tf
  outputs.tf
  README.md
  namespace.tf
  quota.tf
environments/
  dev/
    versions.tf
    backend.tf
    providers.tf
    variables.tf
    main.tf
    outputs.tf
    terraform.tfvars
  prod/
    versions.tf
    backend.tf
    providers.tf
    variables.tf
    main.tf
    outputs.tf
    terraform.tfvars
```

| File of the root | Role |
| --- | --- |
| `.copier-answers.yml` | Answers of the template, read back by `forge update`. Do not edit. |
| `.gitignore` | Excludes the state, the plans and the provider cache. The state carries values in plain text: it must never be committed. |
| `.tflint.hcl` | tflint rule set applied to the project. |
| `Makefile` | Shortcuts: `make init ENV=prod`, `make plan ENV=prod`. |
| `README.md` | This file: how to use the project. |

| File of an environment | Role |
| --- | --- |
| `versions.tf` | Terraform version and providers required by this root. |
| `backend.tf` | Where the state of this environment is kept. |
| `providers.tf` | Configuration of the providers: targeted cluster, context. |
| `variables.tf` | Inputs of the root, taken up from those of the module. |
| `main.tf` | Call of the module, with the values of this environment. |
| `outputs.tf` | Outputs brought up from the module. |
| `terraform.tfvars` | Values of this environment. No secret value. |

## Environments

| `dev` | `boutique-dev` | `dev` | `local` |
| `prod` **(production)** | `boutique-prod` | `plateforme-prod` | `local` |

The namespaces are derived according to the `per_env`
strategy.
Terraform **creates** these namespaces.

## Using the project

With `make`:

```bash
make init  ENV=dev
make plan  ENV=dev
make apply ENV=dev
```

Without `make`, or for a command the Makefile does not cover:

```bash
terraform -chdir=environments/dev init -input=false
terraform -chdir=environments/dev plan -input=false
terraform -chdir=environments/dev apply -input=false
```

Validation, without touching any infrastructure:

```bash
terraform fmt -check -recursive
terraform -chdir=environments/dev init -backend=false
terraform -chdir=environments/dev validate
tflint --recursive
```

`forge validate` chains exactly these commands on every environment.

## Secret values

**No file of this project carries a secret value**, and that will not change:
`terraform.tfvars` is versioned.

No secret variable is necessary as things stand.

The credentials to access the state storage, for their part, are passed at
initialisation time (`terraform init -backend-config="..."`) or through the
environment variables of the provider.

## What to know before applying

- **`terraform destroy` goes beyond the perimeter.** Deleting the namespace
  deletes everything it contains, including what a Helm chart deployed there and
  that Terraform does not know about.
- **The state carries values in plain text.** Generated passwords, private keys:
  the state contains them. The `.gitignore` excludes it from the repository; in a
  team, an encrypted and locked backend is a precondition, not an improvement.
- **Check the context before applying.** Without `config_context`, Terraform goes
  to the cluster the kubeconfig of the machine designates at the time of the
  command. The `kube_context` variable of each `terraform.tfvars` exists to avoid
  it.
