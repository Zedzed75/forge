Boutique en ligne, chaine complete

> File generated by forge. Do not edit it by hand: modify `forge.yml` at the root

This module sets up **the base** the service is deployed on: the partition, its
budget, the identity that deploys there. It does **not** deploy the application
workload — that is the role of a Helm chart, which targets the namespace this
module exposes as an output.

It configures no provider: it is the calling root (`environments/<env>/`) that
decides which cluster is targeted. The module therefore stays callable from any
root.

## Resource families retained

### `namespace` — Creates the namespace the service is deployed in

Sets up the partition itself, with the app.kubernetes.io labels of the service. This is the pivot family: the others attach themselves to it by reference, which gives Terraform the creation order with no explicit depends_on.

Absent, the module assumes the namespace already created by the platform team and merely attaches itself to it by its name.

Sets up: `kubernetes_namespace`.

Points to watch:

- `terraform destroy` deletes the namespace, and therefore **everything** it contains -- including what a Helm chart deployed there and that Terraform does not know about. The destruction goes beyond the perimeter.
- Changing the name of the namespace destroys and recreates it (ForceNew behaviour): the content is lost, with no warning other than the plan line.
- A namespace being deleted stays in the Terminating phase as long as a finalizer has not given back control; Terraform waits, and the wait looks like a hang.

### `quota` — ResourceQuota and LimitRange: the budget of the namespace

Caps what the namespace can consume and gives a default size to the containers that do not declare one.

This is the family that has the most effect on the other domains: as soon as a ResourceQuota covers cpu or memory, the API refuses any pod whose container has no `resources.requests`.

Sets up: `kubernetes_resource_quota`, `kubernetes_limit_range`.

Points to watch:

- As soon as a quota covers `requests.cpu` or `requests.memory`, **every** pod without `resources.requests` is refused at admission. The Helm chart of the same service must therefore declare its requests, otherwise the deployment breaks the day the quota is set up.
- The LimitRange only applies to the pods **created after** it: the pods already in place keep their configuration, and the divergence is only seen at the next restart.
- A quota reduced below the current consumption evicts nothing: it only blocks the subsequent creations. The namespace looks healthy until the next deployment.

## What this module does not do

- **It does not deploy the application.** The namespace it exposes is meant to
  receive a Helm chart or a manifest; the two meet on the name of the namespace,
  and on nothing else.
- **It manages no real secret.** The secret values arrive through
  `TF_VAR_<name>`; those it generates itself live in the Terraform state, which
  must therefore be encrypted.
- **It grants no cluster-wide right.** A `Role` only applies in its namespace, and
  that is deliberate.
